# Blockchain-AI Fusion for Secure and Transparent Data Science Workflows

**Open-source research implementation (Python + optional Hyperledger Fabric).**

Implements synthetic multi-user workflow DAGs, six attack generators, signed provenance commitments, an append-only local *simulation* ledger, optional Hyperledger Fabric chaincode/Gateway integration, ProvSeqGAT (BiGRU + GATv2), learned workflow/step anomaly heads, actor-history trust fusion, adaptive validation, audit reconstruction, baselines, external dataset adapters, statistical evaluation and figure generation.

> **Integrity of scientific results:** The results generated by this code are measured, not fixed to values stated in a manuscript. The local ledger is NOT Fabric. Fabric throughput/latency figures require an actual deployed network. The manuscript's stated WfCommons/OpenML cohorts are not bundled and cannot be claimed as reproduced until the source manifests and conversion rules are independently verified.

## 1. Requirements

- Python 3.10+; PyTorch 2.1+; NumPy; scikit-learn; NetworkX; cryptography.
- Supported on Windows, macOS, Linux, Google Colab; CUDA accelerates training but is not mandatory.
- The graph-attention implementation is **pure PyTorch** (no compiled PyTorch Geometric dependency required).
- Internet and Docker are required **only** for downloading external datasets, installing dependencies, or running genuine Fabric integration.

## 2. Installation

```bash
python -m venv .venv
# Linux/macOS: source .venv/bin/activate
# Windows: .venv\\Scripts\\activate
python -m pip install --upgrade pip
python -m pip install -e '.[experiments,tests]'
python -m blockai --help
pytest -q
```

For a smaller dependency set, use `pip install -e .` (the optional experiments group includes XGBoost, Optuna and OpenML; XGBoost is automatically substituted by a scikit-learn learner if missing). CPU experiments run with `BLOCKAI_CPU_THREADS=2` or a larger value.

## 3. First complete run (smoke test)

```bash
python -m blockai smoke --output results/smoke
```

This **runs** a 96-workflow dataset through generation, random 60/10/30 split, fitted train-only feature scalers, ProvSeqGAT training, threshold selection, baseline comparisons, test predictions, trust scoring, local signed ledger, and 600-dpi figures. Outputs are under `results/smoke`. A smoke run is a functionality test, not a claim about final scientific accuracy.

For an even faster test:

```bash
python -m blockai smoke --n 72 --epochs 2 --skip-baselines --output results/quick
```

## 4. Full synthetic study (paper-scale configuration)

```bash
python -m blockai generate --n 10000 --seed 42 --output datasets/synthetic/workflows.jsonl.gz
python -m blockai experiment --input datasets/synthetic/workflows.jsonl.gz \
    --config configs/experiment.yaml --seed 42 --protocol random \
    --baselines --output results/main
```

The 10,000-trace generator creates exactly **7,000 normal + 3,000 attacked** workflows, 20 templates and 6 balanced *primary* attack types. It adjusts the truncated-normal lengths within `[5,50]` to achieve the manuscript's **240,000 simulated event** budget. Multi-stage attacks may have multiple labels; the primary attack category stays balanced at 500 traces per type.

The experiment's 60/10/30 split yields 6,000 / 1,000 / 3,000 workflows. The test set is not used for training, scaling, model/threshold selection or early stopping.

**Other protocols**

```bash
# Six unseen templates, held apart from training and validation
python -m blockai experiment --input datasets/synthetic/workflows.jsonl.gz \
    --protocol template --seed 42 --output results/template

# Leave this attack type out of *both* training and validation
python -m blockai experiment --input datasets/synthetic/workflows.jsonl.gz \
    --protocol attack --held-out-attack model_replacement \
    --seed 42 --output results/unknown_model_replacement

# Five neural ablations: no GAT, no GRU, no integrity, no actor, no temporal
python -m blockai ablation --input datasets/synthetic/workflows.jsonl.gz \
    --config configs/experiment.yaml --output results/ablations

# Full 40-trial Optuna TPE search (training/validation only)
python -m blockai tune --input datasets/synthetic/workflows.jsonl.gz \
    --config configs/experiment.yaml --trials 40 --output results/optuna

# All ten paper seeds and optional paired baselines
python -m blockai repeats --config configs/experiment.yaml --baselines \
    --output results/repetitions
```

Ten-run results include mean, SD, Student-t 95% intervals, Shapiro-Wilk, paired t, paired Wilcoxon, Holm-adjusted p-values and paired effect sizes.

## 5. Provenance, artifacts and audit

```bash
python -m blockai ledger --backend simulated --limit 50 \
    --input datasets/synthetic/workflows.jsonl.gz --output results/ledger

python -m blockai audit --limit 10 \
    --input datasets/synthetic/workflows.jsonl.gz \
    --model results/main/model --output results/audit.json

python -m blockai artifact-store --input datasets/synthetic/workflows.jsonl.gz \
    --limit 10 --output results/artifacts \
    --key-file results/secrets/artifact.key

# Incremental demonstration of trust-gated local validation
python -m blockai governance-demo --input datasets/synthetic/workflows.jsonl.gz \
    --model results/main/model --auto-audit --output results/governance.json
```

The AES-GCM key is saved with owner-only permissions if it does not already exist. **Back it up securely**; do not commit it. The demonstration ledger uses per-actor ECDSA P-256 and an independent append-only attempt log. Rejected proposals are not treated as committed records.

The `governance-demo` illustrates incremental prefix scoring but is not an independently calibrated online-detection experiment. It uses a *simulated* ledger; genuine Fabric adaptive endorsement is separately provided by the Go chaincode.

## 6. Real-world workflow adapters

**WfCommons (observed tasks and dependency DAG).** Data source: https://github.com/wfcommons/WfInstances

```bash
python -m blockai download --dataset wfcommons --limit 20 --output datasets/wfcommons
python -m blockai external --source wfcommons --input datasets/wfcommons \
    --model results/main/model --inject-attacks \
    --output results/external_wfcommons
```

**OpenML (metadata-only, inferred lifecycle stages).** Data source: https://www.openml.org

```bash
python -m blockai download --dataset openml --limit 50 --output datasets/openml
python -m blockai external --source openml --input datasets/openml \
    --model results/main/model --inject-attacks \
    --output results/external_openml
```

**Essential validity caveats:** WfFormat retains real task dependencies, but absent artifact bytes cannot be cryptographically verified. OpenML provides real experiments, configurations and evaluation information; it does **not** generally provide a true per-step provenance DAG, so its seven workflow stages are **explicitly inferred**. Both corpora have no native attack labels in this repository; the `--inject-attacks` option creates **synthetic** compromises after import. Zero-shot predictions can be produced without the flag, but no attack-classification ground truth is available for scoring. The source data and manifest checksums, not arbitrary manuscript counts, define the external cohort.

## 7. Real Fabric experiment

The repository includes a Go `wfgov` chaincode, a Go Fabric Gateway REST bridge and a two-org official test-network launch helper. **This is a real Fabric integration path, not a Fabric emulator**; it requires Docker and network bootstrap. For step-by-step instructions see [`fabric/README.md`](fabric/README.md).

```bash
# After Docker, official fabric-samples and the Fabric 2.5 tools are installed:
./fabric/network/start-test-network.sh

# In separate terminals, configure the Gateway identity/certificate variables,
# run the Go bridge, then:
export BLOCKAI_GATEWAY_TOKEN='set-a-long-random-token'
python -m blockai ledger --backend fabric --gateway http://127.0.0.1:8080 \
    --input datasets/synthetic/workflows.jsonl.gz --limit 3 \
    --store-private --output results/fabric
```

`--store-private` securely includes salted parameters as Fabric **transient data**, committed atomically to a configured private data collection. Four organizations/eight peers/three orderers from the paper require a separately provisioned four-org network and its agreed endorsement policy; the official two-org test-network is only an integration demonstration. **No Fabric throughput results are bundled or fabricated.**

## 8. Model design

- 40 engineered numeric step features and trainable 16-D step-type / 8-D certified-role embeddings = 64 per step.
- Linear(64→128), LayerNorm, GELU; two-layer BiGRU with 64 hidden units in each direction.
- Two native-PyTorch GATv2 layers: four heads × 32, per-destination softmax, residual connections.
- Attention graph pooling + six workflow-level features; MLP 134→64→1 (workflow probability).
- Separate 128→1 step head (attack localisation); loss = weighted workflow BCE (`pos_weight=2.33`) + 0.3 × step BCE.
- AdamW, cosine LR with warm-up, dropout, gradient clipping, validation PR-AUC early stopping; Youden-J binary threshold and precision-constrained high-risk threshold.
- Mean actor history updated **after** scoring each workflow, so future outcomes cannot influence the current score.

Because the described architecture leaves some implementation choices unspecified, the actual model has approximately **233k trainable parameters**, not the manuscript's approximate 310k. The code reports the actual count. Hyperparameter search can be explicitly launched with `blockai tune` (40 Optuna TPE trials by default). Fixed-configuration experiments and ablations do not silently run Optuna.

## 9. Evaluation & baselines

| Module | Evaluation |
|---|---|
| RuleOnly | Deterministic sequence/access/integrity violations |
| IsolationForest | Unsupervised on normal workflow statistics |
| OneClassSVM | Unsupervised on normal workflow statistics |
| XGBoost | Supervised classifier on aggregated workflow features |
| LSTM_Autoencoder | Normal-only recurrent step-feature reconstruction |
| DeepLog | Normal-only next-step event prediction (GRU approximation) |
| ProvenanceGraph_IF_proxy | IsolationForest on structural DAG statistics, **not original UNICORN** |

The proxy and DeepLog-inspired implementation are not claims to reproduce the original authors' published detectors. All methods use the same held-out workflow IDs. Scores are calibrated only on training/validation. Charts include ROC, PR, confusion matrix, per-attack recall and workflow lengths, generated at 600 dpi.

## 10. Repository layout

- `src/blockai/`: application code and CLI.
- `fabric/chaincode/wfgov/`: Fabric Go chaincode with role/access, step parent commitments, governance feedback and private collection.
- `fabric/gateway/`: certificate-authenticated Go REST bridge for Python clients.
- `fabric/network/`: two-org test-network helper and private data collection configuration.
- `configs/`: reproducible smoke/main experimental settings.
- `tests/`: automated unit/integration tests.
- `examples/`: sample input fixtures and Colab quickstart.
- `docs/`: detailed mathematical mapping, caveats and validation guidance.
- `results/`: generated checkpoints, predictions, charts, manifests, reports (not tracked by default).

## 11. Reporting and limitations

Outputs are explicitly labelled as **simulated**, **Fabric-backed**, **synthetic**, **observed real**, or **inferred real** where appropriate. Results may differ materially from the paper's reported accuracy/F1 and transaction counts. Real committed-transaction latency must be measured on actual peers/orderers and hardware; local Python processing times are not interchangeable. Synthetic actor permissions, source metadata commitments and behavioral anomalies are not equivalent to real-world evidence of compromise.
